# カロナビ デザイナー向け要件定義

最初に渡す資料です。機能は凍結済みです。**見た目だけ**を外注します。新機能の提案・追加は不要です。

画面一覧・導線・空／エラーなどの状態は [01_INFORMATION_ARCHITECTURE.md](./01_INFORMATION_ARCHITECTURE.md) を正とします。納品物は [02_DELIVERABLES.md](./02_DELIVERABLES.md) です。

---

## 1. プロダクト

| 項目 | 内容 |
| --- | --- |
| アプリ名 | **カロナビ** |
| 運営 | AYG |
| ストア名 | **カロナビ**（AYG は出さない） |
| 一言 | エネルギー管理の意思決定支援 |
| タグライン（現行） | 毎日の食事と運動を、やさしく見える化。 |
| 対象 | 24歳前後の日本の会社員 |
| UI 言語 | 日本語のみ |
| 公開目標 | Apple App Store（**iPhone 優先**） |
| Web | Preview のみ。本番公開ではない |

カロナビは、食事管理アプリでも筋トレ記録アプリでもありません。  
「今日、自分は何をすればよいか」を数字で示す、エネルギー管理の意思決定支援です。

---

## 2. 公開範囲と作業分担

- デザイナーの対象は **見た目と画面表現** です。
- 機能・計算・データ保存は実装側が担当します。デザインで機能を増やさないでください。
- 内側（API、メール、Flutter Environment、Apple コンソール）は並行作業です。**この資料に書かない／実装しない**。
- 規約・プライバシー・サポートなど、種機能以外で審査に必要なものは、本文は草案でよいので置き場所だけあります。文面の法務確定は別作業です。
- **サポートメールと公開 URL は未定**です。デザイン上は「サポート」「利用規約」などの導線だけ用意し、実アドレスや本番 URL はプレースホルダで構いません。

---

## 3. デザイン原則

1. **外はシンプル**  
   内部計算は複雑でも、ユーザーには「今日あと何kcal」と次の行動だけが伝わればよい。
2. **入力は最小**  
   忙しい会社員が毎日続けられること。入力項目を増やさない。
3. **医療アプリに見せない**  
   診断・治療・処方・医療機器の印象を出さない。断定しない。
4. **根拠はリンク先**  
   画面上に論文の解説を長く置かない。計算根拠は設定内のリンク先へ。
5. **日本語の日常語**  
   専門用語を前面に出さない。活動量は「座っている時間が長い」など日常語。

避けてほしいこと

- 「治療」「診断」「処方」「治る」「医師推奨」などの医療表現
- ギルト（責め）や罰のトーン。超過は事実として静かに示す
- ダッシュボードの情報過多。ホームの主役は「今日あと何kcal」だけ
- 新しいタブ、課金、広告、機能追加

## 4. 情報設計（固定）

### 下タブ（iPhone）

順番・ラベルは固定です。増やしません。

1. ホーム
2. 食事
3. 運動
4. 体重
5. 設定

広い画面（タブレット／デスクトップ Preview）は、**左サイドバーに同じ 5 つ**です。項目を変えないでください。

### ログイン

- **Google または Apple** のみ
- **ゲストなし**
- ログイン画面に利用規約・プライバシーポリシーへのリンク
- キャンセル・失敗・読み込み中をデザイン対象にする

### 初回（オンボーディング）

順番は固定です。

1. Health を使うか使わないか
2. 基本情報（生年月日・性別・身長・現在体重）
3. 目標（減量 / 維持 / 増量、目標体重、目標日）
4. Health を使わないときだけ、活動量

Health を使う場合、活動量の手選択は出しません。

### ホーム（主役）

ホームの主役は **「今日あと何kcal」** です。

必ず置くもの

- 今日あと何kcal（超過時は超過kcal）
- PFC（タンパク質・脂質・炭水化物）の残り／進捗
- クイック追加：食事 / 運動 / 体重
- 今日の食事
- 今日のアルコール
- 今日の運動

補助で出してよいもの：摂取kcal、運動消費kcal、現在体重、目標の残り日数。主役を邪魔しないこと。

### 食事

記録の入り口は次だけです。増やしません。

- 手入力
- バーコード（**カメラと番号入力の両方を常時表示**。折りたたみ禁止）
- 保存食品（マイ食品）
- 公開食品
- テンプレート

数量は小数可。空欄時は 1 として扱う現行仕様を崩さない。

**アルコールは別フォーム**です。食品マスターに統合しない。

### 運動

- **MET 計算** または **手入力kcal**
- テンプレートあり
- **Health Workout の自動取り込み画面は作らない**

### 体重

一覧・追加・編集・削除ができること。

- 「準備中」プレースホルダは禁止
- グラフは見た目の範囲で入れてよい（機能追加ではない）
- ホームのクイック追加からも同じ追加／編集画面へ

現行 Preview の体重タブは仮の「準備中」表示です。**踏襲しないでください。** デザインでは完成形の一覧を描きます。

### 設定

項目は次で固定です。

- 基本情報
- 目標
- 活動・Health
- マイ食品
- 計算根拠
- 利用規約
- プライバシー
- 運営連絡
- ログアウト
- アカウント削除

運営連絡とアカウント削除の本文・メールアドレス・公開 URL は未定です。画面上の置き場所と、確認ダイアログの見た目だけ作ってください。

## 5. デザイン対象にする状態

見た目のメインパスだけでは不足です。次を必ず描いてください。

| 状態 | 例 |
| --- | --- |
| 空 | 今日の食事がない、体重が1件もない |
| 読込 | ログイン中、バーコード検索中、保存中 |
| エラー | ログイン失敗、検索失敗、保存失敗、カメラ不可。再試行できること |
| 超過 | 今日のkcalが目標を超えたホーム |
| 削除確認 | 確認ダイアログのあと、Snackbar で **Undo（元に戻す）** |

そのほか現行仕様で必要な状態

- 未来日には新規記録を追加できない
- 目標設定の矛盾警告（減量なのに目標体重が現在以上、など）
- Health 非対応端末／Web Preview では Health が使えない旨
- バーコードカメラが使えないとき、番号入力だけで続行できる

## 6. やらないこと

次はデザインしない・提案しないでください。

- 課金
- 広告
- 新しいタブ
- アルコールの食品マスター統合
- 機能追加（SNS、レシピ、コミュニティ、チャット、ウェアラブルの新規画面など）
- Health Workout の自動取り込み画面
- ゲスト利用
- 英語 UI
- 医療アプリ／診断アプリとしての見せ方
- ストア名やアイコンに AYG を出すこと
- 内側（API、メール、Flutter Environment、Apple コンソール）の画面
