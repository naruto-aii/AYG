# カロナビ デザイン仕様

今後の画面変更・新規画面は、この仕様に合わせる。

## 0. この文書について

### 目的

この文書は、カロナビ（AYG）の画面・UIに関する唯一の正とする仕様書である。次のどの立場で作業する人・AIも、この文書だけを読めば正しい方向で手を動かせることを目指す。

- 外部のデザイナー・エンジニアに依頼するとき
- Cursor・Claude Code など複数のAIで横断的に作業するとき
- 画面を作り直す・移植するとき
- 既存画面に機能を追加・修正するとき

### 読み方

1. まず「2. プロダクト思想」を読む。色や数値の前に、何を優先して判断するかを揃える。
2. 新しい画面を作るときは「4. 画面の土台」から順に読む。
3. 既存画面を直すときは「13. 画面一覧と対応状況」で、その画面が既にこの仕様に沿っているか確認してから着手する。
4. 文言を書くときは「11. 文言・トーンのルール」に従う。
5. 迷ったら、憶測で進めずユーザーに確認する（`rules/AI_RULES.md` のルール9）。

### 値の出どころ

値は `lib/theme` と `lib/widgets/design` にあるものだけを書く。既存画面でこれと違う箇所は、今後この仕様にそろえる。Figma原本は本リポジトリでは追跡していない（コード内コメントに「Figma: ◯◯」という対応名だけが残っている）。Figmaの実体を確認したい場合はユーザーに確認すること。

## 1. アプリの概要

カロナビは、食事・運動・体重・目標を横断して管理する「エネルギー管理による意思決定支援アプリ」である（`docs/00_PROJECT.md` 参照）。一般的な食事記録アプリや筋トレ記録アプリではなく、「今日あと何kcal食べられるか」のような日々の判断を、科学的根拠に基づいて数値化し短く提示することが核心価値である。

対象は24歳前後、忙しい日本の会社員。診断・治療のためのアプリではない。ログインが前提（Google / Apple）で、ゲスト利用はない。

技術: Flutter / Dart、バックエンドSupabase。現在はiOSのみを製品として提供している（2026年10月、Flutter WebをGitHub Pagesから外し、iOSアプリに一本化する判断をした。`bef91c3` 参照）。

## 2. プロダクト思想（デザイン判断の軸）

`docs/00_PROJECT.md` のPhilosophyを、UI上の判断基準として言い換えたもの。色や余白で迷ったときより先に、この軸で迷わないようにする。

| 原則 | UIでの意味 |
| --- | --- |
| Evidence First | 根拠のない断定・誇張した表現を画面・文言に出さない。計算根拠は開示できる場所に置く（`CalculationReferencesScreen` など）。 |
| Energy First | ホームの主役は「今日あと」。他の情報はこれを補足する位置づけにする。 |
| Simplicity Outside | 画面に出す文字・数字は最小限。複雑な計算は内部で行い、ユーザーには結果と次の行動だけを見せる。 |
| Complexity Inside | 画面をシンプルにするために、計算やバリデーションを粗くしない。内部ロジックは正確に保つ。 |
| Input Minimum | 新しい入力項目を足すときは、本当に必要か疑う。テンプレート・保存食品・バーコードなど「もう一度入力しない」導線を優先する。 |
| Trust | 分からないことは分からないと伝える。達成を断定しない（例: 「届かない」ことを隠さず画面に出す、計算の前提を明記する）。誇大な謳い文句・不確かな数値の演出をしない。 |

この軸は、競合（あすけん・カロミル等）との比較表現にも適用する。他社を貶す比較はしない（`docs/index.html` のFAQにも明記）。

## 3. 画面構成（情報設計）

### 3.1 全体の流れ

```
起動
 └ SplashScreen（起動演出）
    └ 未ログイン → LoginScreen（Google / Apple）
    └ 初回ログイン → オンボーディング（4画面、下記）
    └ 2回目以降 → MainShellScreen（タブ）
```

### 3.2 オンボーディング（初回のみ、この順番で進む）

1. `HealthSetupScreen` — Health連携の案内（iPhoneのみ表示）
2. `BasicInfoScreen` — 表示名・生年月日・性別・身長・現体重
3. `GoalSetupScreen` — 目標区分（減量/維持/増量）・目標体重・目標日。必要ならカロリー/PFCの手入力もここ
4. `ActivityLevelScreen` — 活動量の選択。完了すると `MainShellScreen` へ

同じ入力項目は、ログイン後の設定画面（3.6）でも編集できる。オンボーディングと設定で同じ `DesignFieldCard` / `DesignInputBox` の組み合わせを使い、見た目をそろえる。

### 3.3 メインタブ

`MainShellScreen` が下部タブの入れ物。タブの並びは **食事・運動・ホーム（中央）・体重・設定**（`DesignTabBar.defaultItems`）。Web版シェルだけ並びが異なる（ホーム・食事・運動・体重・設定）が、これは意図的な差ではなく未整理の差分として残っている（6.1参照）。

| タブ | 画面 | 役割 |
| --- | --- | --- |
| ホーム | `HomeScreen` | 「今日あと」何kcalか、PFCバランス、クイック追加。アプリの顔 |
| 食事 | `FoodTabScreen` | その日の食事一覧。入力方法の切り替え（手入力・バーコード・保存食品・公開食品・テンプレート） |
| 運動 | `WorkoutTabScreen` | その日の運動一覧。種目・時刻・追加消費(net) kcal |
| 体重 | `WeightTabScreen` / `WeightPlaceholderScreen` | 体重の記録・期間別の推移グラフ |
| 設定 | `SettingsScreen` | 各種設定・法務ページ・カロナビ+への入口 |

### 3.4 食事関連

- `FoodFormScreen` — 食事の追加・編集フォーム（主要入力画面）
- `FoodFormNavigation` / `FoodFormTemplateActions` — 入力方法の切り替え・「テンプレートとして保存」などの導線
- `FoodMealRegistrationScreen` — テンプレートから1件を食事として登録
- `BarcodeScannerScreen` — カメラでEAN-13/JANバーコードを読み取る

### 3.5 運動関連

- `ExerciseFormScreen` — 運動の追加・編集フォーム。**この仕様にすでに揃っている唯一の画面**（7章参照）
- `ExerciseFormTemplateActions` — テンプレート導線・一括登録（`WorkoutTemplateApplyScreen`）

### 3.6 体重・履歴

- `WeightRecordScreen` — 体重の記録
- `DayHistoryScreen` — ある1日の食事・運動・体重をまとめて見る
- `HistoryCalendarScreen` — カレンダーから日を選んで `DayHistoryScreen` へ

### 3.7 保存食品・公開食品

- `SavedFoodListScreen` — マイ食品（自分の保存食品）一覧
- `SavedFoodFormScreen` — 保存食品の追加・編集
- `PublicFoodSearchScreen` — 公開食品・文科省データの検索
- `SavedFoodPublishFlow` / `PublishSavedFoodConfirmationScreen` — 非公開食品を公開する一連の確認フロー
- `OfficialFoodDetailScreen` — 文部科学省 日本食品標準成分表データの詳細

### 3.8 テンプレート

- `MealTemplateListScreen` / `MealTemplateFormScreen` / `MealTemplatePickerScreen` — 食事テンプレートの一覧・作成編集・選択
- `WorkoutTemplateScreens`（一覧・フォーム・選択・一括登録 `WorkoutTemplateApplyScreen`）— 運動テンプレート

無料は食事・運動それぞれ4件まで。カロナビ+は無制限（`SubscriptionCatalog.mealTemplateLimit` / `workoutTemplateLimit`）。上限超過時の挙動は12.2参照。

### 3.9 設定配下

- `SettingsBasicInfoScreen` — 基本情報の編集
- `SettingsGoalScreen` — 目標設定の編集
- `SettingsHealthActivityScreen` — Health連携・活動量の編集
- `SettingsFoodMasterScreen` — マイ食品（保存食品・テンプレート）の入口
- `DataSourceScreen` — データの出典
- `CalculationReferencesScreen` — 計算根拠・参考文献（文献引用とプロダクト既定値を区別して出す）
- `DailyCalculationExplanationScreen` — 「今日あと」の計算根拠の説明
- `HowToUseScreen` — 使い方。いまの画面にある操作だけを書く（将来の機能は書かない）
- `LockScreenMealScreen` — ホーム画面ウィジェット・ロック画面への食事テンプレート割り当て（カロナビ+限定）
- `AccountDeletionScreen` — アカウント削除

### 3.10 カロナビ+（サブスクリプション）

- `CalonaviPlusEntryScreen`（`calonavi_plus_flow.dart`） — 課金画面。デザインの実例は `docs/design/calonavi-plus-paywall/` のスクリーンショット参照

### 3.11 法務

- `LegalDocumentScreen` — 利用規約・プライバシーポリシー・サポート・アカウント削除の説明・特定商取引法に基づく表記（`LegalDocument` enumの5種）

## 4. 画面の土台

新しい画面は `DesignPage` を使う。`Scaffold` と `AppBar` で新しい画面を足さない。`AppBar` の見出しは今後使わない（法務ページ `LegalDocumentScreen` は例外として `AppBar` を使っている。閉じるボタンの型として5章・9.9で参照する）。

`DesignPage` の中身は、幅 390 の座標系で書く（`DesignScreen` が土台）。描画時は `画面幅 / 390` を掛け、拡大率の上限は 1.5 である。地の色は `bgPage`。

左右余白は 20。`DesignPage` の `bodyPadding` の初期値は 16 のままなので、新しい画面では `AppSpacing.screenHorizontal`（20）を渡す。下部ボタンの外側余白も左右 20、上下は部品の 6 とする。`bottomBarPadding` の初期値は左右 16・上下 6 のままである。

ブロックとブロックの縦間隔の基準は 16（`AppSpacing.md`）。`AppSpacing.sectionGap` は 24 だが、新しい画面の基準には使わない。

フルスクリーンでポップアップ的に開く画面（カロナビ+の課金画面など）は、左上の「戻る」ではなく右上に閉じる（×）アイコンを置く。`DesignIcon(Symbols.close_rounded)`、サイズ22、色 `AppColors.iconMuted`。`LegalDocumentScreen` の `AppBar` と `CalonaviPlusEntryScreen` が実例。

## 8. 影

`AppShadows.card` は、色 green700 の alpha 0.07、ぼかし 16、オフセット (0, 4)。`DesignCard` の初期状態はこの影を付ける。コードのコメントは「12%」と書いているが、描画している値はalpha 0.07である。仕様の値は0.07。

`AppShadows.elevated` は green700 の alpha 0.12、ぼかし 24、オフセット (0, 8)、spread -2。

`AppShadows.subtle` は green900 の alpha 0.04、ぼかし 12、オフセット (0, 2)。

## 9. コンポーネントカタログ

`lib/widgets/design/` 配下の部品。Figma対応名はコード内コメントのまま記載する。新しい画面はここにある部品を優先して使い、無ければ追加を検討する前にこの一覧を確認する。

### 9.1 カード

中身を載せるカードは `DesignCard`（Figma: 白いカード）。角丸24、色bgSurface（白）、枠なし。内側余白の初期値は14。影は`AppShadows.card`。

`AppCard` の緑枠（`borderGreen`、太さ0.5）は今後使わない。

### 9.2 ボタン

ボタンは `DesignButton`（Figma: Button）。高さ64、左右の内側余白24、角丸はfull。文字はButton/L。無効のときは不透明度0.45。読み込み中のインジケータは20、線幅2。

| スタイル | 背景 | 文字 | 枠 |
| --- | --- | --- | --- |
| primary | bgPrimary | textOnPrimary | なし |
| secondary | bgSecondary | textPrimary | なし |
| outline | 透明 | textBrand | borderGreenToken、太さ1.5 |
| danger | bgSurfaceDanger | textDanger | なし |

右の矢印（24）は、次へ・はじめる・追加・作成・登録など、先へ進むボタンだけに出す。保存・更新・削除には出さない。進むボタンは`showTrailingIcon`の初期値trueのまま。保存・更新・削除はfalse。

主ボタン以外で画面を進める操作はoutline。削除はdanger。

### 9.3 入力

フォームの1項目は、`DesignFieldCard`（Figma: TextFieldの外枠）の中の`DesignInputBox`（Figma: TextFieldの入力欄）とする。食事の追加やアルコールで別の並びになっている項目も、今後はこれに寄せる。

`DesignFieldCard`は、背景bgSurfaceAlt、角丸20、左右の内側余白18、上下の初期値14。アイコン円は36。円と見出しの間隔10、見出しと入力の間隔10。見出しはTitle/M。

`DesignInputBox`は、背景bgSurface、枠borderDefault、角丸16、左右18、上下13。

入力文字はBody/L、色textPrimary。ヒントはBody/L、色textMuted。カーソルはtextBrand。

ラベル左・入力欄右の横並びが要るときは `DesignRowField`（Figma: 07 アルコールを追加など）。小さなラベル＋白い入力枠の最小形は `MiniField`（Figma: MiniField）。

### 9.4 選択・切り替え

- `SelectCard`（Figma: SelectCard） — タイトル・説明・選択状態（チェック円）を持つ縦積みの選択カード。角丸20（`AppRadius.card`）。選択時は背景`bgSurfaceGreenSoft`、枠`borderFocus`太さ2。タイトル横に任意の`badge`（例:「お得」）、右端に任意の`trailing`を置ける（課金プラン選択カードで使用、`lib/screens/subscription/calonavi_plus_flow.dart`参照）。
- `GoalCard`（Figma: GoalCard） — アイコン・タイトル・説明を縦に積む正方形寄りの選択カード。目標区分（減量/維持/増量）選択で使用。角丸16、選択時は背景`bgSurfaceGreenSoft`、枠`borderFocus`太さ2。
- `DesignSegmentGroup`（Figma: Segment） — 横並びのセグメントコントロール。
- `DesignChipGroup`（Figma: Chip） — 期間切り替えなどのチップ群（体重グラフの1週間/1ヶ月/3ヶ月/1年）。

### 9.5 アイコン・バッジ

- `IconCircle`（Figma: IconCircle） — 円の中にアイコンを置く。tone は green/danger/orange/neutral。サイズ初期値44。ベネフィット一覧・設定行の先頭などで使用。

### 9.6 タブバー・ナビゲーション

`DesignTabBar`（Figma: 画面下部のオレンジのタブバー）。並びは `DesignTabBar.defaultItems`（食事・運動・ホーム・体重・設定）。選択中のタブだけがバーから丸く浮き上がり、タブ切り替えでその丸と切り欠きが滑らかに移動する。バーの高さ80。

`FormTabBar`（Figma: formtabs） — 食事の入力方法切り替え（手入力・バーコード等）。

### 9.7 設定行・警告・ステップ

- `SettingsRow`（Figma: SettingsRow） — 設定一覧の1行。state は default/danger。
- `WarnBanner`（Figma: WarnBanner） — 画面内の注意喚起バナー。
- `StepIndicator`（Figma: StepIndicator） — 初回設定の「n/3」のような進捗表示。

### 9.8 ホーム・グラフ系

- `StatItem`（Figma: StatItem） — 目標/摂取/運動の数値表示。
- `MacroBar`（Figma: MacroBar） — PFCの1項目のバー表示。
- `QuickAddCard`（Figma: QuickAddCard） — ホームのクイック追加カード。
- `CalorieRing`（Figma: CalorieRing、164×164） — 12時から反時計回りに伸びる円グラフ。オレンジの点は進捗と連動しない固定の差し色。
- `WeightChart` — 折れ線グラフ（面塗り＋点、最後の点だけ白抜き）。
- `WeightRow`（Figma: WeightRow） — 体重一覧の1行。

### 9.9 ダイアログ・モーダル

- `showAppConfirmDialog`（`lib/widgets/common/app_confirm_dialog.dart`） — 標準の確認ダイアログ（タイトル・本文・確認/キャンセルの2ボタン）。有料機能への案内（例:「こちらは有料の機能です」）など、Yes/Noの意思確認に使う共通部品。
- フルスクリーンの確認・案内（法務ページ、カロナビ+）は `MaterialPageRoute(fullscreenDialog: true)` ＋ 右上×アイコン（4章参照）。

### 9.10 アイコンアセット

ドメインのアイコンは`AppIcon`（`assets/icons`のSVG）。初期サイズ24。UIの矢印などは`DesignIcon`（Material Symbols Rounded、fill 0、grade 0）。初期サイズ24。

`AppIcon`で使えるのは `assets/icons` にあるSVGに限る（alcohol, avocado, barcode, bookmark, calculator, calendar, calorie, camera, document, dumbbell, exercise, gender, goal, heart, height, home, human, information, logout, mail, meal, meat, pen, rice, scale, search, settings, shield, template, time, trash, user）。これ以外のドメインアイコンが要るときは、SVGを追加するかMaterial Symbolsで代替するかを判断する。

`DesignIcon` は Material Symbols Rounded の全アイコンセットが使える（`Symbols.xxx_rounded`）。UI的な操作アイコン（閉じる、戻る、進むなど）や、ベネフィット一覧のようにドメインSVGに無い概念（メモ、ウィジェット、マイクなど）はこちらを使う。

## 11. 文言・トーンのルール

このアプリの文言は、既存コード（`AppStrings`、各画面の表示文）から読み取れる一貫したトーンに従う。新しい文言を書くときもこれに合わせる。

1. **言い切る短文。** 1文を短く切る。接続詞で長くつながない。「〜です。」「〜できます。」で終える。
2. **煽らない・誇張しない。** 「必ず」「簡単に」「誰でも」のような無根拠な強調語は使わない。数字で言えることは数字で言う（例:「無料は食事・運動それぞれ4件まで」）。
3. **絵文字・感嘆符を使わない。** 既存の文言に絵文字は一切出てこない。「！」も基本的に使わない。
4. **ベネフィットは機能の事実で語る。** 課金画面のベネフィットは「◯◯が無制限」「無料は◯件まで」のように、実際の制限・解放内容を具体的に書く。「もっと便利に」のような抽象表現だけで終わらせない。
5. **届かないときは届かないと書く。** 目標に届かない計算結果を隠したり曖昧にしたりしない（Trust原則）。達成を保証する表現を使わない。
6. **他社比較は事実の違いだけを書き、貶さない。**「あすけんやカロミルとの違いは？」のFAQ文言が実例。
7. **ですます調で統一。** 画面文言・ボタンラベル・エラーメッセージすべて敬体。
8. **送り仮名・漢字の開き方に厳密さを求めすぎない。** 既存文言は「カロリー」「たんぱく質」のように一般的な表記揺れを許容している。ただし同一画面内では統一する。
9. **エラーメッセージは原因を言う。** 「購入できませんでした」のように短く事実を言う。解決策が明確な場合のみ添える（例: 「この環境ではアプリ内課金を使えません」）。

## 12. よく使うUXパターン

### 12.1 有料機能への案内パターン

無料ユーザーがカロナビ+限定の機能に触れたとき、以下の順で案内する。

1. `showAppConfirmDialog` で「こちらは有料の機能です」＋具体的な説明＋確認/キャンセルの2択を出す。
2. 確認されたら `showCalonaviPlus()` でカロナビ+の課金画面（`CalonaviPlusEntryScreen`）をフルスクリーンで開く。

実装例: `lib/screens/settings/settings_screen.dart` の `_openMealWidget` / `_openVoiceRegistration`、共通化した `lib/widgets/subscription/subscription_limit_prompt.dart` の `showSubscriptionLimitPrompt`。

### 12.2 無料枠の上限パターン

新規作成（テンプレートなど）で無料枠の上限に当たったときは、保存処理そのものを `SubscriptionLimitExceededException` で止め、12.1のパターンに誘導する。編集（既存の件数を増やさない操作）では上限チェックをしない。実装例: `lib/state/app_controller.dart` の `saveMealTemplate` / `saveWorkoutTemplate`。

### 12.3 削除の確認

削除は `danger` スタイルのボタン＋確認ダイアログ。取り消し可能なものは「元に戻す」付きのスナックバー（`confirmDeleteWithUndo`）を使う。

### 12.4 フォームの基本形

`DesignPage` ＋ `DesignTitleBlock`（見出し）＋ `DesignFieldCard`/`DesignInputBox` を16間隔で積む＋ `bottomBar` に保存ボタン。保存ボタンには矢印を出さない（9.2参照）。

### 12.5 価格・金額表示

StoreKitが返す金額をそのまま使う。アプリ側で金額を計算・整形しない（為替・税込表示はストア任せ）。画面上に固定の金額文字列をハードコードしない。実装例: `SubscriptionProductOffer.localizedPrice`。

## 14. プラットフォーム方針

- 製品として配布するのはiOSのみ（2026年10月〜、`bef91c3`）。Androidは一部コードが残るが製品対象外。Web版はGitHub Pagesから撤去済みで、ローカルのプレビュー・検証用途のみ `lib/main_web.dart` 経由で動かせる。
- テーマはライトモードのみ。ダークモード対応はしない。
- 端末依存の機能（Health連携、ウィジェット、Siri音声登録）はiOS 17以降限定。それ以外のプラットフォームでは該当UIを出さない（`showLockScreenMeal` フラグ等で制御）。
