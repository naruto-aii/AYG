# カロナビ デザイン仕様

今後の画面変更は、この仕様に合わせる。

値は `lib/theme` と `lib/widgets/design` にあるものだけを書く。既存画面でこれと違う箇所は、今後この仕様にそろえる。今回そろえたのは運動タブと、運動の追加・編集だけである。

## 画面の土台

新しい画面は `DesignPage` を使う。`Scaffold` と `AppBar` で新しい画面を足さない。`AppBar` の見出しは今後使わない。

`DesignPage` の中身は、幅 390 の座標系で書く。描画時は `画面幅 / 390` を掛け、拡大率の上限は 1.5 である。地の色は `bgPage`。

左右余白は 20。`DesignPage` の `bodyPadding` の初期値は 16 のままなので、新しい画面では `AppSpacing.screenHorizontal`（20）を渡す。下部ボタンの外側余白も左右 20、上下は部品の 6 とする。`bottomBarPadding` の初期値は左右 16・上下 6 のままである。

ブロックとブロックの縦間隔の基準は 16（`AppSpacing.md`）。`AppSpacing.sectionGap` は 24 だが、新しい画面の基準には使わない。

新しい画面の左右は `screenHorizontal`（20）。ブロック間の縦は `md`（16）。`screenPadding` と `sectionGap` は、このルールでは使わない。

角丸は `AppRadius`。

`AppRadius.card` は 20。`DesignCard` の初期角丸は 24。

## 影

`AppShadows.card` は、色 green700 の alpha 0.07、ぼかし 16、オフセット (0, 4)。`DesignCard` の初期状態はこの影を付ける。

`AppShadows.elevated` は green700 の alpha 0.12、ぼかし 24、オフセット (0, 8)、spread -2。

`AppShadows.subtle` は green900 の alpha 0.04、ぼかし 12、オフセット (0, 2)。

`AppShadows.card` のコメントは「12%」と書いている。描画している値は alpha 0.07 である。仕様の値は 0.07。

## カード

中身を載せるカードは `DesignCard`。角丸 24、色 bgSurface（白）、枠なし。内側余白の初期値は 14。影は `AppShadows.card`。

`AppCard` の緑枠（`borderGreen`、太さ 0.5）は今後使わない。

## ボタン

ボタンは `DesignButton`。高さ 64、左右の内側余白 24、角丸は full。文字は Button/L。無効のときは不透明度 0.45。読み込み中のインジケータは 20、線幅 2。

| スタイル | 背景 | 文字 | 枠 |
| --- | --- | --- | --- |
| primary | bgPrimary | textOnPrimary | なし |
| secondary | bgSecondary | textPrimary | なし |
| outline | 透明 | textBrand | borderGreenToken、太さ 1.5 |
| danger | bgSurfaceDanger | textDanger | なし |

右の矢印（24）は、次へ・はじめる・追加・作成・登録など、先へ進むボタンだけに出す。保存・更新・削除には出さない。進むボタンは `showTrailingIcon` の初期値 true のまま。保存・更新・削除は false。

主ボタン以外で画面を進める操作は outline。削除は danger。

## 入力

フォームの 1 項目は、`DesignFieldCard` の中の `DesignInputBox` とする。食事の追加やアルコールで別の並びになっている項目も、今後はこれに寄せる。

`DesignFieldCard` は、背景 bgSurfaceAlt、角丸 20、左右の内側余白 18、上下の初期値 14。アイコン円は 36。円と見出しの間隔 10、見出しと入力の間隔 10。見出しは Title/M。

`DesignInputBox` は、背景 bgSurface、枠 borderDefault、角丸 16、左右 18、上下 13。

入力文字は Body/L、色 textPrimary。ヒントは Body/L、色 textMuted。カーソルは textBrand。

## アイコン

ドメインのアイコンは `AppIcon`（`assets/icons` の SVG）。初期サイズ 24。UI の矢印などは `DesignIcon`（Material Symbols Rounded、fill 0、grade 0）。初期サイズ 24。

## 並び

`DesignTitleBlock` の下に、間隔 16 でブロックを積む。画面を進めるボタンは `DesignPage` の `bottomBar` に置く。

端末のタブバー部品 `DesignTabBar` の並びは、食事、運動、ホーム、体重、設定。バーの高さは 80。Web シェルの `NavigationBar` の並びは、ホーム、食事、運動、体重、設定。この並びの差は、今回の 7 つの決定には含まれない。コードのまま残し、今後そろえる。

## 運動画面

運動タブと、運動の追加・編集は、この仕様に合わせてある。

運動タブは `DesignPage`。見出しは「運動」（Heading/L）。左右 20。日付の送り、その日の運動一覧、追加ボタンの間隔は 16。一覧の行は、種目名・時刻・追加消費（net）kcal。追加ボタン「運動を追加」は進むボタンなので矢印を出す。保存した記録は、その日の一覧に出る。

運動の追加・編集も `DesignPage`。見出しは「運動を追加」または「運動を編集」。項目は `DesignFieldCard` と `DesignInputBox`。保存と更新、削除に矢印は出さない。削除は danger。

幅 900 以上のとき、以前の入力画面は `AppFormConstraint`（縦に広げない）の中の `ListView` だった。この組み合わせは縦方向の制約が無く、描画が落ちて入力欄が空に見えていた。入力画面は `DesignPage` の縦スクロールに載せ、入力した種目・時間・記録が見える。

## 今後そろえる画面

運動タブと運動の追加・編集以外は、今回直していない。`Scaffold` と `AppBar`、左右 16 や 24、`AppCard`、`AppTextField` の画面が残っている。それらを変えるときは、この仕様の土台・余白 20・見出しの分け方・`DesignCard`・進むボタンだけの矢印・`DesignFieldCard`・縦間隔 16 にそろえる。
