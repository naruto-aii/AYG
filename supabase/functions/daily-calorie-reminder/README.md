# 20:00（日本時間）の通知

サインイン中の iOS ユーザーに、日本時間 20:00 に1通だけ送る。本文はその瞬間の食事、運動、目標から作る。前に組み立てた文は保存しない。

食事か運動を、アプリが前回ホームを計算したあとに記録しても、その行がデータベースに届いていれば 20:00 の文に入る。記録の保存は、いままでどおり保存のたびに同期する。

## 文

1. その日本の暦日に食事も運動も無い: 「今日の食事、運動が登録されてません！今のうちに登録しましょう！」
2. 残りが 0 kcal 以上: 「今日あと{n}kcal食べられます！」
3. 目標を超えている: 「今日は{n}kcalオーバーしてます！{km}kmランニングすればチャラにできますよ！」

残りはホームと同じ式。目標 + 運動の net + その日の Health 上乗せ − 食事 − アルコール。kcal はホームのリングと同じく、小数 0 桁（0.5 は 0 から遠い方）に丸める。

距離はランニングの既存モデル。追加消費 kcal = 1.0 × 体重kg × 距離km。超過 kcal（上の丸めのあと）を、プロフィールの体重で割る。1 桁に丸め、超過が正なら 0.1 未満にはしない。プロフィールに正の体重が無いときだけ、距離の計算に 60 kg を使う。

Health の上乗せは、アプリがその日本の日付に保存した値を使う。日付が違う、または未保存のときは、プロフィール体重の Mifflin–St Jeor と生活活動係数で同じ式を当てる。平滑した体重の目標式そのものはサーバでは再計算しない。目標 kcal は、手入力ならその値、自動なら最後に保存した `auto_food_target_kcal`。

`logged_at` は端末の壁時計をオフセット無しで保存している。日本の暦日は、その UTC 日付成分が Asia/Tokyo の日付と一致する行。

## 時刻

日本に夏時間は無い。20:00 は毎日 11:00 UTC。関数は日本時間の 20 時台以外では送らない。`daily_reminder_deliveries` の主キーが、同じ人と日付の 2 通目を止める。届かなかった一時的な失敗だけ、その日の取り直しを許す。

スケジュールは `supabase/cron/daily_calorie_reminder.sql`。マイグレーションでは流さない。

## シークレット

git や `config.toml` には置かない。

- `APNS_TEAM_ID`
- `APNS_KEY_ID`
- `APNS_PRIVATE_KEY`（APNs 用 `.p8`。Sign in with Apple の鍵とは別）
- `APNS_BUNDLE_ID`（省略時は `com.narutoaii.ayg`）

デバッグと Profile のトークンは sandbox、Release は production。関数はトークンの `apns_environment` で送り先を分ける。

この変更は関数をデプロイせず、マイグレーションも本番へ適用しない。
